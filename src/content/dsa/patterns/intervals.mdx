Calendars, bookings, CPU jobs, flight times — interval problems are everywhere, and they share one move that unlocks almost all of them: **sort first**. Unsorted intervals can overlap anything, anywhere; sorted by start, an interval can only overlap the one just before it. After that, most problems are one linear pass.

<Callout type="tip" title="How to spot it">

- The input is a list of **ranges**: `[start, end]` pairs, meetings, bookings, time slots.
- The question mentions **overlap**, **merge**, **conflict**, **free time**, **rooms needed**, or **remove the fewest**.
- "Can a person attend all meetings?", "how many rooms?", "how many arrows/points to hit all of them?"
- Two sorted lists of intervals to **intersect**.

</Callout>

## Overlap, precisely

Two intervals `[a, b]` and `[c, d]` overlap when **each starts before the other ends**:

```java
boolean overlap = a <= d && c <= b;        // closed intervals: touching endpoints count
boolean overlapHalfOpen = a < d && c < b;  // half-open [a, b): touching endpoints don't
```

Whether touching counts (`[1, 3]` and `[3, 5]`) depends on the problem. Merging calendars usually says yes; "meeting ends at 3, next starts at 3" usually says no. **Ask, or check the examples** — it's the most common source of wrong answers here.

```java
static int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));   // 1. sort by start
    List<int[]> out = new ArrayList<>();
    for (int[] cur : intervals) {
        if (!out.isEmpty() && cur[0] <= out.get(out.size() - 1)[1]) {
            int[] last = out.get(out.size() - 1);
            last[1] = Math.max(last[1], cur[1]);                       // 2. overlaps: extend
        } else {
            out.add(cur);                                              // 3. gap: start a new one
        }
    }
    return out.toArray(new int[0][]);
}
```

Note the `Math.max`: `[1, 10]` followed by `[2, 3]` must stay `[1, 10]`, not shrink to `[1, 3]`.

## Worked problems

### Insert an interval into a sorted, non-overlapping list

Three phases, no sort needed (the list is already sorted): copy everything that ends **before** the new one starts, absorb everything that overlaps, copy the rest.

```java
static int[][] insert(int[][] intervals, int[] add) {
    List<int[]> out = new ArrayList<>();
    int i = 0, n = intervals.length;
    int[] cur = { add[0], add[1] };
    while (i < n && intervals[i][1] < cur[0]) out.add(intervals[i++]);      // entirely before
    while (i < n && intervals[i][0] <= cur[1]) {                             // overlapping: absorb
        cur[0] = Math.min(cur[0], intervals[i][0]);
        cur[1] = Math.max(cur[1], intervals[i][1]);
        i++;
    }
    out.add(cur);
    while (i < n) out.add(intervals[i++]);                                   // entirely after
    return out.toArray(new int[0][]);
}
```

O(n) — no sorting, because the input is already sorted.

### Non-overlapping intervals — remove the fewest

> Remove the minimum number of intervals so the rest don't overlap.

This is a **greedy** problem, and the sort key changes: sort by **end**. Always keep the interval that finishes earliest — it leaves the most room for everything after it.

```java
static int eraseOverlapIntervals(int[][] intervals) {
    if (intervals.length == 0) return 0;
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));   // sort by END
    int kept = 1, end = intervals[0][1];
    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] >= end) { kept++; end = intervals[i][1]; }   // fits after the last kept one
    }
    return intervals.length - kept;
}
```

Why end, not start? Sorting by start would happily keep `[1, 100]` first and then have to drop everything inside it. The earliest-ending interval is never a worse choice than any other first choice — the classic activity-selection argument (see [Greedy](/dsa/patterns/greedy)).

### Minimum arrows to burst balloons

Same idea, closed intervals: one arrow at the end of the earliest-ending balloon bursts every balloon that has already started by then.

```java
static int findMinArrowShots(int[][] points) {
    if (points.length == 0) return 0;
    Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));
    int arrows = 1, at = points[0][1];                      // shoot at the earliest end
    for (int[] p : points) if (p[0] > at) { arrows++; at = p[1]; }
    return arrows;
}
```

### Meeting rooms — maximum overlap with a sweep line

> Minimum number of rooms so that all meetings `[start, end)` can happen.

The answer is the largest number of meetings running at the same moment. Sort starts and ends **separately** and sweep through time: a start takes a room, an end frees one.

```java
static int minMeetingRooms(int[][] meetings) {
    int n = meetings.length;
    int[] starts = new int[n], ends = new int[n];
    for (int i = 0; i < n; i++) { starts[i] = meetings[i][0]; ends[i] = meetings[i][1]; }
    Arrays.sort(starts); Arrays.sort(ends);
    int rooms = 0, best = 0, e = 0;
    for (int s = 0; s < n; s++) {
        while (e < n && ends[e] <= starts[s]) { rooms--; e++; }   // meetings that ended free their rooms
        rooms++;
        best = Math.max(best, rooms);
    }
    return best;
}
```

The `<=` means a meeting ending at 3 frees its room for one starting at 3. An equivalent approach uses a min-heap of end times (see [Heaps](/dsa/patterns/heap-patterns)); the sweep line generalises to "how many X are active at the busiest moment".

### Intersection of two sorted interval lists

Two pointers, one per list. The overlap of the current pair is `[max(starts), min(ends)]`; then drop whichever interval ends first — it can't overlap anything further in the other list.

```java
static int[][] intervalIntersection(int[][] A, int[][] B) {
    List<int[]> out = new ArrayList<>();
    int i = 0, j = 0;
    while (i < A.length && j < B.length) {
        int lo = Math.max(A[i][0], B[j][0]), hi = Math.min(A[i][1], B[j][1]);
        if (lo <= hi) out.add(new int[] { lo, hi });
        if (A[i][1] < B[j][1]) i++; else j++;
    }
    return out.toArray(new int[0][]);
}
```

## Which sort key?

| Goal | Sort by | Why |
| --- | --- | --- |
| Merge / insert / combine | **start** | Overlaps become adjacent |
| Keep the most non-overlapping / fewest removals / fewest points | **end** | Earliest finish leaves the most room |
| Max simultaneous (rooms, peak load) | starts and ends **separately** (sweep) | Count +1 at starts, −1 at ends |

<Callout type="warning" title="Common mistakes">

- **Not sorting** — or sorting by the wrong end for the goal.
- **Touching endpoints** handled inconsistently: decide closed vs half-open from the examples.
- **Shrinking a merged interval**: always `last[1] = max(last[1], cur[1])`.
- **Comparator overflow** with `(a, b) -> a[0] - b[0]` on large coordinates — use `Integer.compare`.
- **Mutating input arrays** you later rely on (merge edits `last[1]` in place — copy if the caller needs the original).

</Callout>

## Interview questions

<QA q="Why do you sort by end time when maximising the number of non-overlapping intervals?">
Choosing the interval that ends earliest leaves the most time for the remaining ones. If an optimal solution started with some other interval, swapping it for the earliest-ending one can't create a conflict (it ends no later), so there's always an optimal solution that makes the greedy choice. Repeating the argument shows greedy by end time is optimal. Sorting by start fails on cases like one long interval covering many short ones.
</QA>

<QA q="How do you compute the minimum number of meeting rooms?">
It equals the maximum number of meetings overlapping at any moment. Sort the start times and end times separately and sweep: each start uses a room, and before counting a start, release every meeting whose end time is at or before it. Track the peak. Alternatively sort meetings by start and keep a min-heap of end times, popping ended meetings; the heap's maximum size is the answer. Both are O(n log n).
</QA>

<Practice task="Given a person's meetings as intervals, can they attend all of them? What's the simplest check after sorting?">

Sort by start, then check each adjacent pair: if any meeting starts before the previous one ends (`cur[0] < prev[1]` for half-open intervals), there's a conflict. O(n log n). It's merge without building the output — you only need to know whether any merge would happen.

</Practice>

<Practice task="Employees' busy schedules are given as lists of intervals. Find the common free time of everyone. Which two steps from this lesson combine to solve it?">

Flatten all busy intervals into one list and **merge** them (sort by start, extend overlaps). The **gaps** between consecutive merged intervals are exactly the times when nobody is busy. O(N log N) for N total intervals; with k already-sorted lists, a heap-based k-way merge avoids a full sort.

</Practice>

<Takeaways>

- Sort first. By start to merge/insert; by end to keep the most / remove the fewest; starts and ends separately for peak overlap.
- Overlap: each starts before the other ends. Decide whether touching counts.
- Merging extends with `max`; inserting uses three phases on an already-sorted list.
- The sweep line (+1 at starts, −1 at ends) answers "how many at the busiest moment".

</Takeaways>
