Graphs have a reputation for being the hardest topic — and they're not, once you see that **almost every graph problem is BFS or DFS with a `visited` set**. A grid of land and water is a graph. A course list with prerequisites is a graph. Accounts sharing an email form a graph. The skill is recognising the graph hiding in the problem; the traversal itself is a template you already half-know from [trees](/dsa/patterns/tree-dfs) — a tree is just a graph with no cycles, which is why trees didn't need a `visited` set.

<Callout type="note" title="New to graphs?">

This lesson assumes you know what nodes, edges and an adjacency list are, and how BFS and DFS move. If not, read [Graphs](/dsa/data-structures/graphs) in Data Structures Basics first. It has step-through visuals.

</Callout>

<Callout type="tip" title="How to spot it">

- A **grid** where cells connect to neighbours (islands, regions, flood fill, mazes).
- Things **connected** by relationships: friends, cities and roads, words that differ by one letter, accounts sharing emails.
- "**Number of** connected groups", "**can you reach** X from Y", "**fewest steps**".
- Something **spreads** step by step from one or many starting points (rot, fire, infection, distance from the nearest 0).
- Dependencies and ordering → [topological sort](/dsa/patterns/topological-sort); weighted shortest paths → [Dijkstra](/dsa/patterns/shortest-paths).

</Callout>

## Representing a graph

```java
// Adjacency list (most problems): node → neighbours
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
for (int[] e : edges) { graph.get(e[0]).add(e[1]); graph.get(e[1]).add(e[0]); }   // drop the 2nd add if directed

// Grid: the graph is implicit — neighbours are the 4 adjacent cells
static final int[][] DIRS = { { 1, 0 }, { -1, 0 }, { 0, 1 }, { 0, -1 } };
for (int[] d : DIRS) {
    int nr = r + d[0], nc = c + d[1];
    if (nr >= 0 && nc >= 0 && nr < rows && nc < cols) { /* neighbour */ }
}
```

The `DIRS` array is the most reused four lines in grid problems — write it once, loop over it, never hand-write four neighbour checks.

## DFS: explore everything reachable

```java
static int numIslands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++)
        for (int c = 0; c < grid[0].length; c++)
            if (grid[r][c] == '1') { count++; sink(grid, r, c); }   // a new, unvisited island
    return count;
}

static void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;   // off-grid, water, or visited
    g[r][c] = '0';                                                     // mark visited (here: sink the land)
    for (int[] d : DIRS) sink(g, r + d[0], c + d[1]);
}
```

**The connected-components template:** loop over every node; each time you find an unvisited one, that's a new component — explore it fully, marking everything you touch. Count the starts.

Marking visited **by modifying the grid** saves memory; if you mustn't modify the input, use a `boolean[][] visited`.

### Returning something from DFS: max area of an island

```java
static int area(int[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != 1) return 0;
    g[r][c] = 0;
    return 1 + area(g, r + 1, c) + area(g, r - 1, c) + area(g, r, c + 1) + area(g, r, c - 1);
}
```

Same shape as tree DFS: the answer for a cell is 1 plus the answers from its neighbours — with the visited mark preventing double counting.

## BFS: explore in rings of distance

BFS visits nodes in order of their distance from the start, so the **first time it reaches a node is by a shortest path** (in an unweighted graph). Use BFS whenever the question says "fewest steps", "shortest", or "minimum time".

```java
Deque<int[]> queue = new ArrayDeque<>();
queue.offer(start);
markVisited(start);                         // mark when you ENQUEUE, not when you poll
while (!queue.isEmpty()) {
    int[] cur = queue.poll();
    for (each neighbour nb of cur) {
        if (!visited(nb)) { markVisited(nb); queue.offer(nb); }
    }
}
```

Marking when **enqueuing** matters: if you mark when polling, the same cell can be added to the queue many times by different neighbours, blowing up time and memory.

### Shortest path in a binary matrix (8 directions)

```java
static int shortestPathBinaryMatrix(int[][] grid) {
    int n = grid.length;
    if (grid[0][0] == 1 || grid[n - 1][n - 1] == 1) return -1;
    int[][] dist = new int[n][n];                         // 0 = unvisited; doubles as the visited mark
    dist[0][0] = 1;
    Deque<int[]> q = new ArrayDeque<>(List.of(new int[] { 0, 0 }));
    while (!q.isEmpty()) {
        int[] cell = q.poll();
        if (cell[0] == n - 1 && cell[1] == n - 1) return dist[n - 1][n - 1];
        for (int dr = -1; dr <= 1; dr++) for (int dc = -1; dc <= 1; dc++) {
            int nr = cell[0] + dr, nc = cell[1] + dc;
            if (nr >= 0 && nc >= 0 && nr < n && nc < n && grid[nr][nc] == 0 && dist[nr][nc] == 0) {
                dist[nr][nc] = dist[cell[0]][cell[1]] + 1;
                q.offer(new int[] { nr, nc });
            }
        }
    }
    return -1;
}
```

## Multi-source BFS: many starting points at once

When something spreads from **several** sources simultaneously, put **all of them** in the queue before starting. BFS levels then measure the distance from the *nearest* source.

```java
static int orangesRotting(int[][] grid) {
    int R = grid.length, C = grid[0].length, fresh = 0;
    Deque<int[]> q = new ArrayDeque<>();
    for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) {
        if (grid[r][c] == 2) q.offer(new int[] { r, c });   // every source at minute 0
        else if (grid[r][c] == 1) fresh++;
    }
    int minutes = 0;
    while (!q.isEmpty() && fresh > 0) {
        int size = q.size();                                   // one level = one minute
        for (int i = 0; i < size; i++) {
            int[] cell = q.poll();
            for (int[] d : DIRS) {
                int nr = cell[0] + d[0], nc = cell[1] + d[1];
                if (nr >= 0 && nc >= 0 && nr < R && nc < C && grid[nr][nc] == 1) {
                    grid[nr][nc] = 2;
                    fresh--;
                    q.offer(new int[] { nr, nc });
                }
            }
        }
        minutes++;
    }
    return fresh == 0 ? minutes : -1;                          // unreachable fresh oranges
}
```

The same trick solves "distance of every cell to the nearest 0", "walls and gates", and "as far from land as possible": start from all the targets and expand outward, instead of running a BFS from every cell.

## Thinking in reverse

Some problems are much easier from the **other end**:

- **Surrounded regions** — instead of finding enclosed `O`s, run DFS from every `O` on the **border**; everything those reach is safe, everything else gets captured.
- **Pacific Atlantic water flow** — instead of asking, for every cell, whether water can flow to both oceans, run BFS **uphill** from each ocean's edge and intersect the two reachable sets.

If "from every cell" means repeating a search n times, ask whether one search from the targets answers the same question.

## DFS or BFS?

| Need | Use |
| --- | --- |
| Count / explore connected components | Either (DFS is shortest to write) |
| Size or shape of a region | DFS (return values combine nicely) |
| Fewest steps, shortest path (unweighted) | BFS |
| Spreading from many sources | Multi-source BFS |
| Very large grids (deep recursion risk) | BFS or iterative DFS |

Both are **O(V + E)** — for a grid, O(rows × cols).

<Callout type="warning" title="Common mistakes">

- **No visited marking** — infinite loops on cycles (graphs, unlike trees, have them).
- **Marking visited on poll instead of enqueue** in BFS — duplicates in the queue.
- **Bounds checks after array access** — check `r`, `c` first.
- **Recursion depth** — a 1000 × 1000 grid of land is a million-deep DFS: use BFS or an explicit stack.
- **Running a BFS from every cell** when one multi-source BFS would do.

</Callout>

## Interview questions

<QA q="Why does BFS find the shortest path in an unweighted graph?">
BFS explores nodes in order of their distance from the start: all nodes at distance 1, then distance 2, and so on, because the queue processes a whole level before any node of the next level. So the first time a node is reached, it is by a path with the fewest possible edges. This only holds when every edge has the same cost; with weights, use Dijkstra.
</QA>

<QA q="How would you find the distance from every cell to the nearest gate in a grid?">
Run one multi-source BFS: put every gate in the queue at distance 0, then expand level by level, setting each empty cell's distance the first time it's reached. Each cell is visited once, so it's O(rows × cols), instead of running a separate BFS from every cell or every gate.
</QA>

<Practice task="Word ladder: transform 'hit' into 'cog' changing one letter at a time, every intermediate word in a dictionary. What are the nodes and edges, and how do you find neighbours efficiently?">

Nodes are words; an edge joins words that differ in exactly one letter. Shortest transformation = **BFS**. Don't compare every pair of words (O(n²·L)); instead, for a word, generate all L × 25 one-letter variations and check each against a `HashSet` of the dictionary. Remove words from the set as you enqueue them (that's the visited mark). O(n · L · 26) with L the word length.

</Practice>

<Practice task="Clone a connected undirected graph. Why do you need a map, and what does it double as?">

Traverse (BFS or DFS) from the given node. Keep a `Map<Node, Node>` from each original node to its copy. When visiting a neighbour that isn't in the map yet, create its copy and schedule it; either way, link the current copy to the neighbour's copy. The map **is** the visited set — and it's also what stops cycles from creating duplicate copies.

</Practice>

<Takeaways>

- Find the graph: cells, words, people, accounts — nodes; adjacency, one-letter difference, shared email — edges.
- DFS for components and region properties; BFS for fewest steps.
- Always keep a visited mark; in BFS, mark when you enqueue.
- Multi-source BFS: start from all sources at once to get distance to the nearest.
- Reverse the search (from borders or targets) when "from every cell" would repeat work.

</Takeaways>
