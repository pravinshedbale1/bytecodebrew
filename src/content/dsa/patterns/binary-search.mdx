Binary search is famous for being simple to describe and hard to get right. Off-by-one errors, infinite loops, `<` versus `<=`, `mid` versus `mid + 1` — most people memorise three or four slightly different versions and mix them up under pressure. This lesson replaces all of them with **one template** that you never have to adjust, built on a single question: *where does a condition flip from false to true?*

<Callout type="tip" title="How to spot it">

- The input is **sorted** (or sorted-then-rotated), and you need to find a position or value.
- The constraints are large (n up to 10⁵ or more) and the problem hints at **O(log n)**.
- You need the **first** or **last** position of something, or where something **would be inserted**.
- There's a yes/no condition that is **false for a while, then true forever** (monotonic) — even if the data isn't an array. (That's [binary search on the answer](/dsa/patterns/binary-search-on-answer).)

</Callout>

## The one idea: find the first true

Almost every binary search question can be phrased as: *"Given a condition that is `false, false, …, false, true, true, …, true` across a range, find the first `true`."*

| Question | Condition `ok(i)` |
| --- | --- |
| Where is `x` (or where would it go)? | `a[i] >= x` |
| First occurrence of `x` | `a[i] >= x`, then check `a[i] == x` |
| Last occurrence of `x` | first `a[i] > x`, minus one |
| Smallest value whose square exceeds `n` | `r * r > n` |
| Minimum of a rotated sorted array | `a[i] <= a[last]` |

Once you have the condition, the code is always the same:

```java
/** Smallest i in [lo, hi) with ok(i) true, or hi if there is none. ok must be false…false, true…true. */
static int firstTrue(int lo, int hi, IntPredicate ok) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;      // no overflow; mid < hi always
        if (ok.test(mid)) hi = mid;        // mid could be the answer: keep it in range
        else lo = mid + 1;                 // mid is not: discard it and everything left of it
    }
    return lo;                             // lo == hi: the first true (or hi if none)
}
```

Step through it. The row under the cells is the condition, false…true, but it stays hidden (?) except where `mid` probes it: binary search never needs the rest. Each probe drops half of the candidates. Try the other two examples: a missing x gives its insert position, and "last x" reuses the same template with `a[i] > x`.

<FirstTrueViz examples={['lower', 'insert', 'upper']} />

Why this template never loops forever or skips the answer:

- The answer is always inside `[lo, hi]` (with `hi` meaning "none").
- `mid` rounds down, so `mid < hi`: `hi = mid` always shrinks the range, and so does `lo = mid + 1`.
- When `lo == hi`, the range has one candidate left — the answer.

You never write `mid - 1`, never use `<=` in the loop, and never special-case "found it".

## Worked problems

### Lower bound, search and insert position

```java
static int lowerBound(int[] a, int x) { return firstTrue(0, a.length, i -> a[i] >= x); }   // also the insert position

static int search(int[] a, int x) {
    int i = lowerBound(a, x);
    return i < a.length && a[i] == x ? i : -1;
}
```

### First and last position of x

```java
static int[] searchRange(int[] a, int x) {
    int first = firstTrue(0, a.length, i -> a[i] >= x);
    if (first == a.length || a[first] != x) return new int[] { -1, -1 };
    int afterLast = firstTrue(0, a.length, i -> a[i] > x);    // first element bigger than x
    return new int[] { first, afterLast - 1 };
}
```

"Last true" is always "first true of the opposite condition, minus one". You never need a second template.

### Integer square root

```java
static int mySqrt(int x) {
    // largest r with r*r ≤ x  =  (first r with r*r > x) − 1
    return firstTrue(0, 46341, r -> (long) r * r > x) - 1;    // 46341² exceeds Integer.MAX_VALUE
}
```

Two details: the search range doesn't have to be array indexes — it's any range of integers — and `r * r` must be computed in `long`, or it overflows for large `r`.

### Find the minimum in a rotated sorted array

`[4, 5, 6, 7, 0, 1, 2]` — everything before the rotation point is **greater** than the last element; everything from it onward is **at most** the last element. That's a false…true condition:

```java
static int findMin(int[] a) {
    int last = a[a.length - 1];
    return a[firstTrue(0, a.length, i -> a[i] <= last)];
}
```

### Search in a rotated sorted array

Here the classic form is clearer. At every step, **one half is sorted** — check whether the target lies inside that sorted half; if so go there, otherwise go to the other half.

```java
static int searchRotated(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[lo] <= a[mid]) {                              // left half [lo, mid] is sorted
            if (a[lo] <= target && target < a[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                                            // right half [mid, hi] is sorted
            if (a[mid] < target && target <= a[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
```

(An alternative that reuses the template: find the rotation point with `findMin`'s condition, then run a normal lower bound on the correct half.)

Step through it. The dots above the cells show the two ascending runs. At each probe the bracket marks the sorted half, and the only question is whether the target lies between that half's two ends.

### Find a peak element

> Neighbours always differ. Return any index that is greater than its neighbours.

If `a[i] > a[i + 1]`, the array is going down at `i`, so there's a peak at `i` or to its left. The condition "going down at i" may not be monotonic over the whole array, but the template still finds *a* point where it flips from false to true — and that point is a peak.

```java
static int findPeakElement(int[] a) {
    return firstTrue(0, a.length - 1, i -> a[i] > a[i + 1]);   // the last index if it never goes down
}
```

The same template, unchanged, on three different conditions. In the square root the cells are plain integers, not an array. The rotated minimum uses `a[i] <= a[last]`. The peak shows the template ending on a flip even when the condition isn't monotonic.

### Search a 2D matrix

When each row is sorted and starts after the previous row ends, the matrix **is** one sorted array of `R × C` elements. Map index `k` to `(k / C, k % C)`:

```java
static boolean searchMatrix(int[][] m, int target) {
    int R = m.length, C = m[0].length;
    int i = firstTrue(0, R * C, k -> m[k / C][k % C] >= target);
    return i < R * C && m[i / C][i % C] == target;
}
```

## Debugging checklist

| Symptom | Likely cause |
| --- | --- |
| Infinite loop | `lo = mid` somewhere (instead of `mid + 1`) with `mid` rounding down |
| Answer off by one | Searching for "last true" with the first-true template without the −1 |
| Wrong on duplicates | Stopped at any match instead of the first `>= x` |
| Overflow on large inputs | `(lo + hi) / 2`, or `mid * mid` in `int` |
| Fails on empty input | Accessing `a[lo]` without checking `lo < a.length` |

<Callout type="warning" title="Common mistakes">

- **Mixing templates** — pick the first-true one and phrase every problem as a condition.
- **A condition that isn't monotonic** — binary search only works if it's false…false, true…true.
- **`(lo + hi) / 2` overflow** — use `lo + (hi - lo) / 2`.
- **Forgetting the "not found" case** — the template returns `hi` (often `a.length`); check before indexing.
- **Rotated arrays with duplicates** — `a[lo] == a[mid]` breaks the "which half is sorted" test; the worst case becomes O(n).

</Callout>

## Interview questions

<QA q="How do you avoid infinite loops in binary search?">
Make sure every iteration shrinks the range. With lo < hi, mid computed as lo + (hi − lo) / 2 rounds down, so mid is strictly less than hi; then hi = mid and lo = mid + 1 both shrink the range. Infinite loops come from writing lo = mid while mid rounds down — in that case, round mid up instead, or switch to the first-true template.
</QA>

<QA q="What property must a problem have for binary search to apply?">
A monotonic condition: there is a yes/no test over an ordered range of candidates that is false up to some point and true from then on (or the reverse). Sorted data gives this for comparisons with a target, but it also appears without arrays — 'can we finish with capacity c?' becomes true once c is large enough — which is binary search on the answer.
</QA>

<Practice task="Given a sorted array of letters and a target letter, return the smallest letter strictly greater than the target, wrapping around to the first letter if none is greater. Write the condition for firstTrue.">

Condition: `letters[i] > target`. `int i = firstTrue(0, n, k -> letters[k] > target);` If `i == n`, nothing is greater, so wrap: return `letters[0]`; otherwise `letters[i]`. Equivalently `letters[i % n]`. The point of the exercise: "strictly greater" is just a different condition, not a different template.

</Practice>

<Practice task="Count how many times x occurs in a sorted array in O(log n). Express it with two calls to the template.">

`firstTrue(0, n, i -> a[i] > x) − firstTrue(0, n, i -> a[i] >= x)` — the index where values become bigger than x, minus the index where they become at least x. If x is absent, both calls return the same index and the count is 0. No special cases.

</Practice>

<Takeaways>

- Phrase every binary search as "find the first index where a monotonic condition becomes true".
- One template: `while (lo < hi) { mid = lo + (hi − lo) / 2; if (ok(mid)) hi = mid; else lo = mid + 1; }`.
- Last true = (first true of the opposite condition) − 1.
- The search range can be any integer range, not just array indexes; use `long` for products.
- Rotated arrays: compare with the last element, or use "one half is always sorted".

</Takeaways>
