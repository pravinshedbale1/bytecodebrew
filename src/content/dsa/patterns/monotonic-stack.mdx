"For each day, how many days until a warmer temperature?" The brute force looks right from each day until it finds a warmer one — O(n²) on a long cold spell. A **monotonic stack** answers it in one pass. It's one of the most surprising patterns the first time you see it, and one of the most reusable once it clicks: next greater element, stock spans, the largest rectangle in a histogram, and sliding-window maximum all use it.

<Callout type="note" title="New to stacks and deques?">

This lesson assumes you know how a stack and a deque work. If not, read [Stacks & Queues](/dsa/data-structures/stacks-and-queues) in Data Structures Basics first. It has step-through visuals.

</Callout>

<Callout type="tip" title="How to spot it">

- "For each element, find the **next (or previous) greater / smaller** element" — or its distance.
- "How far can each element **extend** left/right before hitting something smaller/bigger?" (histograms, spans, visibility).
- Sums or counts over **all subarrays** of their minimum or maximum.
- "Smallest/largest number after removing k digits" — keep a **greedy increasing** sequence.
- "Maximum (or minimum) of every window of size k" — the **monotonic deque**.
- "Design a queue with getMax / getMin in O(1)", or a window that needs its **max and min** — a **min/max queue**.
- A DP that takes the best of the **last k** states — a max queue over the DP values.

</Callout>

## The idea: a stack of things still waiting for an answer

Walk left to right. The stack holds indexes that **haven't found their next greater element yet**. When a new element arrives, it is the answer for every waiting element smaller than it — pop them all and record it. Then the new element joins the waiting list.

Because we pop everything smaller before pushing, the waiting values are always in **decreasing** order from bottom to top — that's the "monotonic" part.

Step through it. Striped bars are still waiting on the stack; when a bigger one arrives, an arrow shows which waiting bars it answers. The temperatures example records the distance instead of the value, and the last one flips the comparison for the next smaller element.

<NextGreaterViz examples={['nge', 'temps', 'nse']} />

```java
static int[] nextGreater(int[] a) {
    int[] ans = new int[a.length];
    Arrays.fill(ans, -1);                                  // default: none to the right
    Deque<Integer> stack = new ArrayDeque<>();             // indexes; their values decrease toward the top
    for (int i = 0; i < a.length; i++) {
        while (!stack.isEmpty() && a[stack.peek()] < a[i])
            ans[stack.pop()] = a[i];                       // a[i] is the next greater for each popped index
        stack.push(i);
    }
    return ans;
}
```

**Why O(n):** every index is pushed once and popped at most once. The inner `while` does at most n pops in total.

### The four variants, one template

| Want | Pop while top is… | Stack values are… |
| --- | --- | --- |
| Next **greater** | `<` current | decreasing |
| Next **greater or equal** | `<=` current | strictly decreasing |
| Next **smaller** | `>` current | increasing |
| Next **smaller or equal** | `>=` current | strictly increasing |

For **previous** greater/smaller, use the same loop: after popping, the element left on top of the stack *is* the previous one (or none if empty). Or scan right to left.

Step through the template **one comparison at a time**, with the stack drawn beside the array. Each step compares the new element `a[i]` with the top of the stack and either pops (the comparison holds) or stops (it doesn't). The examples cover all four variants, and show the difference between pushing **indexes** (the usual choice: the value is one lookup away, and the index gives distances like "days until warmer") and pushing **values** (fine when you only need the value, as in Next Greater Element I, where values are distinct).

<StackSideViz examples={['ng', 'values', 'temps', 'ns', 'pg', 'ps']} />

Two things to notice as you step:

- **Why stopping early is safe.** When the top doesn't satisfy the comparison, nothing below it can either: the stack is monotonic, so everything below the top is even further away from qualifying.
- **Next vs previous.** For *next*, the answer is written when an element is **popped** (the newcomer answers it). For *previous*, the answer is read **after** the pops, from whatever is left on top.

## Worked problems

### Daily temperatures — distance instead of value

```java
static int[] dailyTemperatures(int[] t) {
    int[] ans = new int[t.length];                           // 0 = no warmer day
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[stack.peek()] < t[i]) {
            int j = stack.pop();
            ans[j] = i - j;                                  // storing indexes gives distances for free
        }
        stack.push(i);
    }
    return ans;
}
```

### Next greater element in a circular array

Walk the array **twice** (indexes `0 … 2n − 1`, using `i % n`), but only push during the first lap — the second lap just resolves the elements still waiting.

```java
static int[] nextGreaterCircular(int[] a) {
    int n = a.length;
    int[] ans = new int[n];
    Arrays.fill(ans, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < 2 * n; i++) {
        int v = a[i % n];
        while (!stack.isEmpty() && a[stack.peek()] < v) ans[stack.pop()] = v;
        if (i < n) stack.push(i);
    }
    return ans;
}
```

### Largest rectangle in a histogram (hard, classic)

For each bar, the widest rectangle using it as the **shortest** bar extends left and right until it meets a **smaller** bar. Keep an **increasing** stack. When a bar is popped, the bar that popped it is the first smaller one on the right, and the bar beneath it on the stack is the first smaller one on the left — so the popped bar knows its full width.

```java
static int largestRectangleArea(int[] h) {
    Deque<Integer> stack = new ArrayDeque<>();               // increasing heights
    int best = 0;
    for (int i = 0; i <= h.length; i++) {
        int cur = i == h.length ? 0 : h[i];                  // a final 0 flushes every remaining bar
        while (!stack.isEmpty() && h[stack.peek()] >= cur) {
            int height = h[stack.pop()];
            int left = stack.isEmpty() ? -1 : stack.peek();  // first smaller bar on the left
            best = Math.max(best, height * (i - left - 1));  // i = first smaller bar on the right
        }
        stack.push(i);
    }
    return best;
}
```

The **sentinel** (a height-0 bar after the end) saves a second cleanup loop — a trick worth reusing.

Step through it: every pop draws the rectangle that bar can make, and the best one stays outlined.

### Sum of subarray minimums — counting contributions

> Sum the minimum of every subarray.

Instead of enumerating O(n²) subarrays, ask: **how many subarrays have `a[i]` as their minimum?** That's `(i − left) × (right − i)`, where `left` is the previous smaller element and `right` the next smaller-or-equal one. Two monotonic passes give both:

```java
static long sumSubarrayMins(int[] a) {
    int n = a.length;
    int[] left = new int[n], right = new int[n];
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {                            // previous STRICTLY smaller
        while (!stack.isEmpty() && a[stack.peek()] >= a[i]) stack.pop();
        left[i] = stack.isEmpty() ? -1 : stack.peek();
        stack.push(i);
    }
    stack.clear();
    for (int i = n - 1; i >= 0; i--) {                       // next smaller OR EQUAL
        while (!stack.isEmpty() && a[stack.peek()] > a[i]) stack.pop();
        right[i] = stack.isEmpty() ? n : stack.peek();
        stack.push(i);
    }
    long total = 0;
    for (int i = 0; i < n; i++) total += (long) a[i] * (i - left[i]) * (right[i] - i);
    return total;
}
```

The **asymmetry** (strict on one side, non-strict on the other) is deliberate: with duplicate values, it makes each subarray's minimum belong to exactly one index. Using strict comparisons on both sides would count `[2, 2]` twice. The reference solution checks this against brute force on thousands of arrays with many duplicates.

### Remove k digits — a greedy increasing stack

> Remove k digits from a number to make it as small as possible: `"1432219"`, k = 3 → `"1219"`.

A smaller digit further left beats anything after it, so whenever the current digit is smaller than the previous kept digit, drop the previous one (while you still can):

```java
static String removeKdigits(String num, int k) {
    StringBuilder stack = new StringBuilder();               // kept digits, non-decreasing
    for (char c : num.toCharArray()) {
        while (k > 0 && stack.length() > 0 && stack.charAt(stack.length() - 1) > c) {
            stack.deleteCharAt(stack.length() - 1);
            k--;
        }
        stack.append(c);
    }
    stack.setLength(stack.length() - k);                     // still must remove some: drop from the end
    int i = 0;
    while (i < stack.length() - 1 && stack.charAt(i) == '0') i++;   // strip leading zeros
    String out = stack.substring(i);
    return out.isEmpty() ? "0" : out;
}
```

### Number of Visible People in a Queue (1944): each pop is someone you can see

> People with distinct heights stand in a line, looking right. Person `i` sees person `j` if everyone between them is shorter than both. Count, for each person, how many people they see. `[10, 6, 8, 5, 11, 9]` → `[3, 1, 2, 1, 1, 0]`.

Looking right from person `i`, you see a staircase: each visible person is taller than everyone before them, up to and including the first person **taller than you**, who blocks the rest. Scan from the right with a stack of people who could still be seen from further left (decreasing from bottom to top). For person `i`:

- every height **shorter** than `heights[i]` that you pop is a person `i` sees, and they are now hidden behind `i` for everyone further left, so popping them loses nothing;
- if the stack is still non-empty, its top is the first taller person: one more.

<VisiblePeopleViz examples={['lesson', 'rising']} />

```java
public int[] canSeePersonsCount(int[] heights) {
    int n = heights.length;
    int[] ans = new int[n];
    Deque<Integer> st = new ArrayDeque<>();                 // heights still visible from the left
    for (int i = n - 1; i >= 0; i--) {
        while (!st.isEmpty() && st.peek() < heights[i]) { st.pop(); ans[i]++; }   // seen, then hidden by i
        if (!st.isEmpty()) ans[i]++;                        // the first taller person
        st.push(heights[i]);
    }
    return ans;
}
```

It's the "previous greater" template with one change: instead of only reading the answer at the top, **count the pops**.

## The monotonic deque: sliding-window maximum

> Maximum of every window of size k.

A heap would give O(n log k). A **deque** of indexes with **decreasing** values gives O(n): the front is always the window's maximum. When a new element arrives, smaller elements at the back can **never** be a maximum again (the new one is bigger and stays longer), so drop them. When the front slides out of the window, drop it too.

```java
static int[] maxSlidingWindow(int[] a, int k) {
    int[] out = new int[a.length - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();                  // indexes, values decreasing front → back
    for (int i = 0; i < a.length; i++) {
        if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();        // front left the window
        while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();     // can never be max again
        dq.offerLast(i);
        if (i >= k - 1) out[i - k + 1] = a[dq.peekFirst()];
    }
    return out;
}
```

Step through it: watch values leave from the back when a bigger one arrives, and from the front when they slide out of the window.

<SlidingMaxViz examples={['mixed', 'falling', 'rising']} />

The same algorithm one comparison at a time, with the deque drawn as a lane (front on the left, back on the right). Each step makes exactly one decision: pop the back, stop, push, drop the expired front, or read the answer.

## Min queue and max queue

The deque in Sliding Window Maximum is really a **max queue**: a queue that can also tell you its largest value in O(1). The window is the queue: values join at the right and leave at the left. Interviewers also ask for it directly: *"Design a queue with push, pop and getMax, all O(1)."* (A min queue is the same with the comparisons flipped.)

Next to the queue, keep a deque `best` of the values that could still become the maximum, in decreasing order:

- **push x**: before adding `x` to the back of `best`, remove every value **smaller** than `x` from the back. Those values arrived earlier, so they leave the queue before `x` does; while `x` is in the queue they can never be the maximum. Throwing them out now is safe.
- **pop**: the value leaving the queue is at the front of `best` only if it's the current maximum; remove it there too.
- **max**: the front of `best`.

Equal values stay (the comparison is strict), so popping one copy of the maximum doesn't lose the other.

<MaxQueueViz examples={['max', 'min']} />

```java
class MaxQueue {
    private final Deque<Integer> q = new ArrayDeque<>(), best = new ArrayDeque<>();   // best: decreasing

    void push(int x) {
        q.offerLast(x);
        while (!best.isEmpty() && best.peekLast() < x) best.pollLast();   // can never be the max again
        best.offerLast(x);
    }

    int pop() {
        int x = q.pollFirst();
        if (best.peekFirst() == x) best.pollFirst();                       // it was the max
        return x;
    }

    int max() { return best.peekFirst(); }
}
```

Each value enters `best` once and leaves at most once, so every operation is **O(1) amortised**.

**The other classic answer: two stacks.** A [min stack](/dsa/patterns/design-data-structures) stores, with each entry, the min (or max) of everything below it. A queue can be built from two stacks (push onto `in`; pop from `out`, refilling it from `in` only when it's empty). Combine the two ideas: each stack knows its own max, so the queue's max is the larger of the two tops.

```java
class MaxQueueTwoStacks {
    private final Deque<int[]> in = new ArrayDeque<>(), out = new ArrayDeque<>();   // {value, max of this stack so far}

    private static void push(Deque<int[]> s, int x) { s.push(new int[] { x, s.isEmpty() ? x : Math.max(x, s.peek()[1]) }); }

    void push(int x) { push(in, x); }

    int pop() {
        if (out.isEmpty()) while (!in.isEmpty()) push(out, in.pop()[0]);   // reverse: the oldest is now on top
        return out.pop()[0];
    }

    int max() {
        int m = Integer.MIN_VALUE;
        if (!in.isEmpty()) m = in.peek()[1];
        if (!out.isEmpty()) m = Math.max(m, out.peek()[1]);
        return m;
    }
}
```

Both are O(1) amortised. The deque version is shorter; the two-stack version is what to reach for when an interviewer says "using only stacks". A heap would work too, but at O(log n) per operation, and removing the oldest element from a heap needs lazy deletion (see [Designing with a heap](/dsa/patterns/design-data-structures#designing-with-a-heap-lazy-deletion)).

### Longest subarray with max − min ≤ limit (1438)

> Return the length of the longest subarray in which every two elements differ by at most `limit`.

"Every two elements differ by at most `limit`" means **max − min ≤ limit**. Shrinking a valid window keeps it valid, so this is a [sliding window](/dsa/patterns/sliding-window), and the window needs its max **and** its min at every step: a max queue and a min queue side by side. When the window gets too wide, move `l` forward; a value leaving the window also leaves a deque if it is at that deque's front.

<LimitWindowViz examples={['lesson', 'tight']} />

```java
public int longestSubarray(int[] nums, int limit) {
    Deque<Integer> maxQ = new ArrayDeque<>(), minQ = new ArrayDeque<>();   // values: decreasing / increasing
    int l = 0, best = 0;
    for (int r = 0; r < nums.length; r++) {
        while (!maxQ.isEmpty() && maxQ.peekLast() < nums[r]) maxQ.pollLast();
        maxQ.offerLast(nums[r]);
        while (!minQ.isEmpty() && minQ.peekLast() > nums[r]) minQ.pollLast();
        minQ.offerLast(nums[r]);
        while (maxQ.peekFirst() - minQ.peekFirst() > limit) {               // too wide: drop nums[l]
            if (maxQ.peekFirst() == nums[l]) maxQ.pollFirst();
            if (minQ.peekFirst() == nums[l]) minQ.pollFirst();
            l++;
        }
        best = Math.max(best, r - l + 1);
    }
    return best;
}
```

O(n). A `TreeMap<value, count>` of the window gives the same answer in O(n log n) and is a fine first answer in an interview.

### Continuous Subarrays (2762): count windows instead of measuring them

> Count the subarrays in which every two elements differ by at most 2. `[5, 4, 2, 4]` → `8`.

The same window as 1438, asking a different question. If `[l, r]` is valid, so is every `[l', r]` with `l ≤ l'`. So for each end `r`, find the smallest valid `l` and **all `r − l + 1` subarrays ending at `r` count**. This "count the starts" step turns any longest-window solution into a counting one.

```java
public long continuousSubarrays(int[] nums) {
    Deque<Integer> maxQ = new ArrayDeque<>(), minQ = new ArrayDeque<>();   // indexes this time
    long count = 0;
    for (int l = 0, r = 0; r < nums.length; r++) {
        while (!maxQ.isEmpty() && nums[maxQ.peekLast()] <= nums[r]) maxQ.pollLast();
        maxQ.offerLast(r);
        while (!minQ.isEmpty() && nums[minQ.peekLast()] >= nums[r]) minQ.pollLast();
        minQ.offerLast(r);
        while (nums[maxQ.peekFirst()] - nums[minQ.peekFirst()] > 2) {
            l++;
            if (maxQ.peekFirst() < l) maxQ.pollFirst();      // left the window
            if (minQ.peekFirst() < l) minQ.pollFirst();
        }
        count += r - l + 1;                                    // every start in [l, r]
    }
    return count;
}
```

Storing **indexes** in the deques (instead of values, as in 1438) makes "has this left the window?" a simple `index < l` check. The count reaches about 5 × 10⁹, so use a `long`.

### Count Subarrays With Cost Less Than or Equal to K: check the condition is monotone

> The cost of a subarray is (max − min) × length. Count the subarrays with cost at most `k`.

Before reaching for a sliding window, check that **shrinking a valid subarray keeps it valid**. Here it does: removing an end element can only lower the spread, and it always lowers the length, so the cost never goes up. That's all a sliding window needs, so the code is Continuous Subarrays with a different test in the inner `while`:

```java
while ((long) (nums[maxQ.peekFirst()] - nums[minQ.peekFirst()]) * (r - l + 1) > k) { … }
```

### Count Prime-Gap Balanced Subarrays: a window over some of the elements

> Count the subarrays that contain at least two primes, where the largest and smallest prime differ by at most `k`.

Two conditions, and each one gives one end of the range of valid starts for a fixed end `r`:

- **spread ≤ k** gets harder as the start moves left (more primes), so it gives a **lowest** start `l`. Slide `l` with a max queue and a min queue that only ever hold **prime** indexes; non-primes don't change the spread.
- **at least two primes** gets easier as the start moves left, so it gives a **highest** start: the second-latest prime at or before `r` (call it `prev`).

Every start in `[l, prev]` works: add `prev − l + 1` when it is positive. Sieve the primes up to `max(nums)` first.

```java
int count = 0, last = -1, prev = -1;                      // the two latest prime indexes
for (int l = 0, r = 0; r < nums.length; r++) {
    if (isPrime[nums[r]]) {
        prev = last; last = r;
        // push r onto maxQ and minQ, then: while (max − min > k) { l++; drop fronts < l; }
    }
    if (prev >= l) count += prev - l + 1;
}
```

### Count Subarrays With Fixed Bounds (2444): three positions, no window

> Count the subarrays whose minimum is exactly `minK` and whose maximum is exactly `maxK`. `[1, 3, 5, 2, 7, 5]`, minK = 1, maxK = 5 → `2`.

This one looks like a min/max queue problem, but the min and max are **fixed values**, so you don't need to track them. For a fixed end `r`, a start works when there is no value outside `[minK, maxK]` in between, and the subarray contains at least one `minK` and one `maxK`. Remember three positions:

- `bad`: the last index holding a value outside `[minK, maxK]`,
- `lastMin` and `lastMax`: the last index of `minK` and of `maxK`.

The valid starts are `bad + 1 … min(lastMin, lastMax)`:

<FixedBoundsViz examples={['lesson', 'ones']} />

```java
public long countSubarrays(int[] nums, int minK, int maxK) {
    long count = 0;
    int bad = -1, lastMin = -1, lastMax = -1;
    for (int i = 0; i < nums.length; i++) {
        if (nums[i] < minK || nums[i] > maxK) bad = i;
        if (nums[i] == minK) lastMin = i;
        if (nums[i] == maxK) lastMax = i;
        count += Math.max(0, Math.min(lastMin, lastMax) - bad);
    }
    return count;
}
```

O(n) time, O(1) space. When `minK == maxK` the same index counts for both, which is exactly right: `[1, 1, 1, 1]` with 1 and 1 gives all 10 subarrays.

### A max queue over DP values: Jump Game VI (1696) and Constrained Subsequence Sum (1425)

Some DPs take the best of the **last k** states: `dp[i] = nums[i] + max(dp[i − k … i − 1])`. Scanning the last k values is O(nk). The last k states are a sliding window, so a max queue of `dp` values makes each step O(1).

```java
public int maxResult(int[] nums, int k) {                    // 1696: best score reaching the last index
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];
    Deque<Integer> dq = new ArrayDeque<>(List.of(0));        // indexes, dp decreasing
    for (int i = 1; i < n; i++) {
        if (dq.peekFirst() < i - k) dq.pollFirst();          // too far back to jump from
        dp[i] = nums[i] + dp[dq.peekFirst()];
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.offerLast(i);
    }
    return dp[n - 1];
}

public int constrainedSubsetSum(int[] nums, int k) {         // 1425: a subsequence may skip at most k − 1 elements
    int n = nums.length, best = Integer.MIN_VALUE;
    int[] dp = new int[n];                                   // best sum of a subsequence ending at i
    Deque<Integer> dq = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (!dq.isEmpty() && dq.peekFirst() < i - k) dq.pollFirst();
        dp[i] = nums[i] + Math.max(0, dq.isEmpty() ? 0 : dp[dq.peekFirst()]);   // extend the best, or start here
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();
        dq.offerLast(i);
        best = Math.max(best, dp[i]);
    }
    return best;
}
```

### A min queue over prefix sums: Shortest Subarray with Sum at Least K (862)

With negative numbers a plain sliding window fails: adding an element can **lower** the sum. Work with prefix sums `p` instead: subarray `[i, j)` has sum `p[j] − p[i]`, and we want the smallest `j − i` with `p[j] − p[i] ≥ k`. Keep a deque of candidate starts with **increasing** prefix values:

- **From the front**: while `p[j] − p[front] ≥ k`, that start has found its shortest partner (any later `j` is longer), so record `j − front` and drop it.
- **From the back**: if `p[back] ≥ p[j]`, start `j` is both later and smaller, so it is always at least as good; drop `back`.

```java
public int shortestSubarray(int[] nums, int k) {
    int n = nums.length, best = n + 1;
    long[] p = new long[n + 1];
    for (int i = 0; i < n; i++) p[i + 1] = p[i] + nums[i];
    Deque<Integer> dq = new ArrayDeque<>();                  // prefix indexes, p increasing
    for (int j = 0; j <= n; j++) {
        while (!dq.isEmpty() && p[j] - p[dq.peekFirst()] >= k) best = Math.min(best, j - dq.pollFirst());
        while (!dq.isEmpty() && p[dq.peekLast()] >= p[j]) dq.pollLast();
        dq.offerLast(j);
    }
    return best <= n ? best : -1;
}
```

<Callout type="warning" title="Common mistakes">

- **Pushing values instead of indexes** — you lose distances and can't tell when an element has left a window.
- **Wrong comparison** (`<` vs `<=`) for the variant you need — use the table above.
- **Strict on both sides** in contribution counting — double-counts equal values.
- **Forgetting the leftovers** after the loop (they get −1 or 0), or forgetting a sentinel to flush them.
- **Overflow** in contribution sums — use `long`.

</Callout>

## Interview questions

<QA q="Why is the monotonic stack solution O(n) even though there's a while loop inside the for loop?">
Each index is pushed onto the stack exactly once and popped at most once. The total number of pops across the entire run is therefore at most n, so the while loop contributes O(n) work overall, and the algorithm is O(n) time with O(n) space for the stack.
</QA>

<QA q="How does the largest-rectangle-in-histogram algorithm know each bar's width?">
It keeps bar indexes in increasing order of height. When a bar is popped because the current bar is lower, the current index is the first smaller bar to its right, and the index left on top of the stack is the first smaller bar to its left. The rectangle with the popped bar as its shortest bar spans strictly between those two, giving width i − left − 1.
</QA>

<Practice task="Online stock span: for each new price, return how many consecutive days (including today) the price was at most today's. Which variant of the template, and what do you store?">

It's **previous greater** with a stack of `{price, span}` pairs. For a new price, pop every entry with price ≤ today's and add their spans to today's span (starting at 1); push `{price, span}`. The popped days are absorbed into today's entry, so each day is pushed and popped once — O(1) amortised per call. Storing the span (instead of re-walking) is what keeps it linear.

</Practice>

<Practice task="Maximal rectangle of 1s in a binary matrix. How do you reduce it to the histogram problem?">

Process row by row, maintaining `heights[j]` = number of consecutive 1s ending at the current row in column j (reset to 0 on a 0). Each row's `heights` is a histogram; run the largest-rectangle algorithm on it and take the maximum over rows. O(rows × cols). Recognising "2D problem = 1D problem per row" is a recurring trick.

</Practice>

<Takeaways>

- A monotonic stack holds indexes still waiting for their next greater/smaller element; a new element resolves the ones it beats.
- Pop condition and strictness decide the variant; storing indexes gives distances and widths.
- Each element is pushed and popped once → O(n).
- Contribution counting: element × (left choices) × (right choices), strict on one side only.
- Monotonic deque: window maximum in O(n) — drop dominated elements from the back, expired ones from the front.

</Takeaways>
