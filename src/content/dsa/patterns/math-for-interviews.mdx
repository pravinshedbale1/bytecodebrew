Many people skip maths because it feels like a separate subject they "were never good at". But interview maths is a short, fixed list: **gcd, primes, fast power, modular arithmetic, overflow, digits and random sampling**. Each one is a tiny template you can learn in an afternoon. These problems are often marked Easy or Medium, and they're a cheap way to lose an interview if you've never seen the trick. This lesson collects the tricks.

<Callout type="tip" title="How to spot it">

- "Return the answer **modulo 10⁹ + 7**". You need modular arithmetic and probably fast power or nCr.
- **Divisibility**, **primes**, factors, "greatest common", "least common multiple".
- **Huge exponents** (n up to 10⁹ or more) call for exponentiation by squaring.
- **Digits** of a number: reverse, palindrome, sum of digits, trailing zeros.
- **Random**: shuffle, pick uniformly from a stream, build one random generator from another.
- "Without using `*`, `/` or `%`", or "it might overflow": see the overflow section and [Bit Manipulation](/dsa/patterns/bit-manipulation).

</Callout>

## GCD and LCM: Euclid's algorithm

`gcd(a, b) = gcd(b, a mod b)`, because any divisor of a and b also divides `a mod b`. The numbers shrink at least as fast as Fibonacci numbers, so it's O(log min(a, b)):

```java
static int gcd(int a, int b) {
    while (b != 0) { int t = a % b; a = b; b = t; }
    return a;
}

static long lcm(int a, int b) { return (long) a / gcd(a, b) * b; }   // divide first: avoids overflow
```

GCD appears in fraction simplification, "largest tile that fits both sides", cycles in rotations (rotating an array by k moves `gcd(n, k)` separate cycles) and line slopes, where you divide `dy` and `dx` by their gcd to get a hashable key.

## Primes

**One number:** trial division up to √n. If n has a factor bigger than √n, it also has one smaller than √n.

```java
static boolean isPrime(int n) {
    if (n < 2) return false;
    for (int d = 2; (long) d * d <= n; d++) if (n % d == 0) return false;
    return true;
}
```

`d * d <= n` avoids computing a square root, and the `long` cast avoids overflow near `Integer.MAX_VALUE`.

**All primes up to n:** use the **sieve of Eratosthenes**. Every number the outer loop reaches that is still unmarked is prime, and it crosses out its multiples:

Step through it: each prime crosses out its multiples starting from its square, and the small number shows which prime did it.

<MathViz examples={['sieve']} />

```java
static boolean[] sieve(int n) {
    boolean[] composite = new boolean[n + 1];
    for (int p = 2; (long) p * p <= n; p++)
        if (!composite[p])
            for (int m = p * p; m <= n; m += p) composite[m] = true;   // smaller multiples were crossed out already
    return composite;
}
```

It runs in O(n log log n), which is effectively linear. **Prime factorisation** uses the same √n idea: divide out each factor completely, and whatever remains above 1 is itself a prime.

```java
static List<Integer> primeFactors(int n) {
    List<Integer> out = new ArrayList<>();
    for (int d = 2; (long) d * d <= n; d++)
        while (n % d == 0) { out.add(d); n /= d; }
    if (n > 1) out.add(n);                         // what remains is a prime bigger than √(original)
    return out;
}
```

## Fast power: exponentiation by squaring

To compute `x^n` for n up to 10¹⁸, use the binary digits of n:

- `x^13 = x^8 · x^4 · x^1`, because 13 is `1101` in binary.
- Square `x` at every step.
- Multiply the square into the result whenever the current bit is 1.

That's O(log n) multiplications:

```java
static long modPow(long base, long exp, long m) {
    long result = 1;
    base %= m;
    while (exp > 0) {
        if ((exp & 1) == 1) result = result * base % m;
        base = base * base % m;
        exp >>= 1;
    }
    return result;
}
```

The same loop works for doubles (`Pow(x, n)`, with negative `n` meaning `1/x`) and even for matrices. Matrix power computes the n-th Fibonacci number in O(log n). One classic trap: `-n` overflows when `n == Integer.MIN_VALUE`, so convert to `long` first:

```java
static double myPow(double x, int n) {
    long e = n;
    if (e < 0) { x = 1 / x; e = -e; }
    double result = 1;
    while (e > 0) {
        if ((e & 1) == 1) result *= x;
        x *= x;
        e >>= 1;
    }
    return result;
}
```

## Modular arithmetic: "return it mod 10⁹ + 7"

Answers that grow exponentially (counting paths, arrangements) are reported modulo the prime `MOD = 1_000_000_007`. The rules:

| Operation | Safe form in Java |
| --- | --- |
| Addition | `(a + b) % MOD` |
| Subtraction | `((a - b) % MOD + MOD) % MOD` (Java's `%` can be negative) |
| Multiplication | `a * b % MOD` with `a`, `b` as `long` (two values under 10⁹ fit in a `long` product) |
| Division by b | Multiply by `b`'s **inverse**: `modPow(b, MOD - 2, MOD)` (Fermat's little theorem, since MOD is prime) |

Take the mod **after every operation**, not at the end. The intermediate values overflow long before the final answer.

**Binomial coefficients** `nCr mod p` come up in counting problems. Precompute factorials and inverse factorials once; then each query is O(1):

```java
static class Binomial {
    final long[] fact, inv;
    Binomial(int n) {
        fact = new long[n + 1];
        inv = new long[n + 1];
        fact[0] = 1;
        for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
        inv[n] = modInverse(fact[n]);
        for (int i = n; i > 0; i--) inv[i - 1] = inv[i] * i % MOD;       // 1/(i−1)! = i / i!
    }
    long nCr(int n, int r) {
        if (r < 0 || r > n) return 0;
        return fact[n] * inv[r] % MOD * inv[n - r] % MOD;
    }
}
```

For example, the number of grid paths that move only right and down is `C(R + C − 2, R − 1)`. That's a one-line answer where [Grid DP](/dsa/patterns/dp-grid) takes O(R·C).

## Overflow and digits

**Check before you multiply.** To reverse an integer's digits safely, compare with `Integer.MAX_VALUE / 10` *before* computing `r * 10 + d`:

```java
static int reverse(int x) {
    int r = 0;
    while (x != 0) {
        int d = x % 10;                            // negative for negative x: the sign carries through
        if (r > Integer.MAX_VALUE / 10 || (r == Integer.MAX_VALUE / 10 && d > 7)) return 0;
        if (r < Integer.MIN_VALUE / 10 || (r == Integer.MIN_VALUE / 10 && d < -8)) return 0;
        r = r * 10 + d;
        x /= 10;
    }
    return r;
}
```

The digit loop `d = x % 10; x /= 10` is the core of every digit problem: palindrome numbers, digit sums, happy numbers, adding numbers stored as digits. When a language-level shortcut is allowed, using a `long` and checking the range at the end is also fine. Say which you're doing.

**Trailing zeros of n!** Each trailing zero needs a factor of 10, which means a 2 and a 5. There are always more 2s than 5s, so count the 5s: multiples of 5 contribute one, multiples of 25 another, multiples of 125 another, and so on.

```java
static int trailingZeroes(int n) {
    int count = 0;
    for (long p = 5; p <= n; p *= 5) count += n / p;   // multiples of 5, of 25 (a second 5), of 125…
    return count;
}
```

## Randomness

**Shuffle (Fisher–Yates).** For `i` from the end down to 1, swap `a[i]` with a random index in `0..i`. Each of the n! orders is equally likely. Picking from `0..n−1` at every step instead is a famous bug: it produces nⁿ equally likely outcomes, which can't divide evenly into n! orders.

```java
static void shuffle(int[] a, Random rnd) {
    for (int i = a.length - 1; i > 0; i--) {
        int j = rnd.nextInt(i + 1);                // 0..i inclusive — not 0..n−1
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

**Reservoir sampling.** To pick one item uniformly from a stream of unknown length in O(1) memory, keep the k-th item with probability 1/k:

```java
static int reservoir(Iterator<Integer> stream, Random rnd) {
    int chosen = -1, seen = 0;
    while (stream.hasNext()) {
        int x = stream.next();
        seen++;
        if (rnd.nextInt(seen) == 0) chosen = x;    // keep the new item with probability 1/seen
    }
    return chosen;
}
```

Why it's uniform: item i is chosen when it arrives (probability 1/i) and then survives every later replacement. Item j replaces it with probability 1/j, so it survives j with probability (j − 1)/j. The product telescopes:

> 1/i · i/(i+1) · (i+1)/(i+2) · … · (n−1)/n = **1/n**.

**Probability basics** come up in follow-ups:

- P(A and B) = P(A) · P(B) only when A and B are **independent**.
- P(A or B) = P(A) + P(B) − P(A and B).
- "Mutually exclusive" (can't both happen) is not the same as "independent". Two mutually exclusive events with non-zero probability are, in fact, dependent.

The reference solution tests both the shuffle and reservoir sampling for uniformity over many runs.

<Callout type="warning" title="Common mistakes">

- **Overflow before the check**: `a * b` with two `int`s overflows before you take `% MOD`. Cast to `long` first.
- **Negative remainders**: in Java `-7 % 3 == -1`. Use `Math.floorMod`, or add `MOD` and take `%` again.
- **`-n` when `n == Integer.MIN_VALUE`**: convert to `long` first.
- **Taking the mod only at the end.**
- **Biased shuffles**: the random index must come from `0..i`, not `0..n−1`.
- **Comparing doubles with `==`**: use a tolerance.

</Callout>

## Interview questions

<QA q="Why does exponentiation by squaring need only O(log n) multiplications?">
Write n in binary. x to the power n is the product of x to the powers of two that correspond to the 1-bits of n, and each of those powers is the square of the previous one. The loop squares the base once per bit and multiplies it into the result when the bit is set, so it does at most two multiplications per bit, and n has about log₂ n bits. With a modulus applied after every multiplication, the numbers also stay small.
</QA>

<QA q="How do you divide when the answer must be returned modulo 10⁹ + 7?">
You can't divide the remainders directly. Instead multiply by the modular inverse of the divisor. Because 10⁹ + 7 is prime, Fermat's little theorem gives the inverse of b as b raised to the power MOD − 2, computed with fast power in O(log MOD). For many divisions, such as binomial coefficients, precompute factorials and inverse factorials once so each nCr is O(1).
</QA>

<Practice task="Given rand5(), which returns 1..5 uniformly, implement rand7(). (CtCI 16.23.) Why can't you just compute rand5() + rand5() mod 7?">

Two calls give `5 · (rand5() − 1) + rand5()`, which is uniform on 1..25. Keep only results 1..21, which is three full copies of 1..7, and **retry** on 22..25. Return `(v − 1) % 7 + 1`. Each value then has exactly 3 chances out of 21. The expected number of rounds is 25/21, about 1.2.

The sum of two rand5() calls is **not** uniform: a total of 6 can happen five ways, but 2 only one way. So any formula built on it is biased. This method is called rejection sampling, and it's the standard way to build one uniform generator from another.

</Practice>

<Practice task="Count the integers in 1..n that are divisible by a or b (n up to 10¹⁸). What's the formula, and where can it go wrong?">

Use inclusion–exclusion: `n / a + n / b − n / lcm(a, b)`, which removes the double-counted multiples of both.

Pitfalls:

- `lcm(a, b)` can overflow, so compute it as `a / gcd(a, b) * b` in `long`, and cap it at n + 1 if it gets large.
- Using `a * b` instead of the lcm is wrong when a and b share factors.

With three numbers, add back the triple intersection. If the question instead asks for the k-th such number, combine this count with [binary search on the answer](/dsa/patterns/binary-search-on-answer).

</Practice>

<Takeaways>

- GCD by Euclid in O(log n); LCM = a / gcd · b to avoid overflow.
- Primes: trial division to √n; the sieve for all primes up to n in O(n log log n).
- Fast power squares the base and multiplies on 1-bits: O(log n).
- Mod after every operation; divide by multiplying with the Fermat inverse; precompute factorials for nCr.
- Check overflow before multiplying; Fisher–Yates for shuffles; reservoir sampling for streams.

</Takeaways>
