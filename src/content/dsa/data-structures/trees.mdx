Arrays and lists are lines: every element has one before it and one after it. A **tree** branches: each element can have several "next" elements, its **children**. That shape fits anything hierarchical: folders, company org charts, HTML pages, the moves in a game. It also makes searching fast. In a well-shaped tree, each step down discards a large part of the data, which is how databases and Java's `TreeMap` find keys in O(log n).

## How a tree is stored

In interviews a binary tree is a set of linked nodes, like a linked list with two `next` references:

```java
static class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int v) { val = v; }
}
```

You're given the `root`, and an empty tree is `null`. An n-ary tree uses `List<Node> children` instead of `left` and `right`. A **complete** tree can also live in an array with no references at all; that's how [heaps](/dsa/data-structures/heaps) work.

| Type | Rule | Why it matters |
| --- | --- | --- |
| **Binary tree** | At most 2 children per node | The default interview tree |
| **Full** | Every node has 0 or 2 children | Expression trees, Huffman codes |
| **Complete** | All levels full except the last, which fills from the left | Fits in an array: heaps |
| **Perfect** | All levels completely full | 2^h − 1 nodes; height = log₂(n + 1) |
| **Balanced** | Subtree heights differ by at most 1 everywhere | Height stays O(log n) |
| **Degenerate** | Every node has one child | Really a linked list; height n |
| **Binary search tree (BST)** | Left subtree smaller, right subtree larger, at every node | Search, insert, delete in O(height) |
| **Self-balancing BST** | A BST that rebalances itself (AVL, red-black) | Guaranteed O(log n): `TreeMap`, `TreeSet` |
| **N-ary tree** | Any number of children | File systems, the DOM |
| **Trie** | N-ary, one edge per character | Prefix search; see [Tries](/dsa/patterns/tries) |
| **Heap** | Complete tree; parent ≤ children (min-heap) | Priority queues; see [Heaps](/dsa/data-structures/heaps) |

The three depth-first orders are the same recursion. Only the position of the "visit" line changes:

```java
static void preorder(TreeNode n, List<Integer> out) {   // node, left, right
    if (n == null) return;
    out.add(n.val); preorder(n.left, out); preorder(n.right, out);
}

static void inorder(TreeNode n, List<Integer> out) {    // left, node, right — sorted for a BST
    if (n == null) return;
    inorder(n.left, out); out.add(n.val); inorder(n.right, out);
}

static void postorder(TreeNode n, List<Integer> out) {  // left, right, node
    if (n == null) return;
    postorder(n.left, out); postorder(n.right, out); out.add(n.val);
}
```

Level order uses a **queue** instead of recursion: take a node from the front, add its children to the back.

```java
static List<Integer> levelOrder(TreeNode root) {        // breadth-first with a queue
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> q = new ArrayDeque<>(List.of(root));
    while (!q.isEmpty()) {
        TreeNode n = q.poll();
        out.add(n.val);
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
    }
    return out;
}
```

Every traversal is O(n) time. The space is O(h) for the recursion stack (depth-first) or O(width) for the queue (level order).

## Binary search trees

A BST adds one rule: **left < node < right**, at every node. Search then becomes a walk down one path:

]} />

```java
static boolean contains(TreeNode root, int x) {
    while (root != null) {
        if (x == root.val) return true;
        root = x < root.val ? root.left : root.right;   // discard the other half
    }
    return false;
}

static TreeNode insert(TreeNode root, int x) {
    if (root == null) return new TreeNode(x);
    if (x < root.val) root.left = insert(root.left, x);
    else if (x > root.val) root.right = insert(root.right, x);   // equal: already present
    return root;
}
```

Deletion has three cases:

- **No children**: just remove the node.
- **One child**: replace the node with its child.
- **Two children**: copy in the value of the **in-order successor** (the leftmost node of the right subtree), then delete that successor.

The reference solution tests all three against `TreeSet`.

## Operations and their cost

| Operation | Balanced BST (`TreeMap`) | Unbalanced BST, worst case | Plain binary tree |
| --- | --- | --- | --- |
| Search | O(log n) | O(n) | O(n): must check everything |
| Insert / delete | O(log n) | O(n) | — |
| Min / max | O(log n) | O(n) | O(n) |
| Sorted iteration | O(n) (inorder) | O(n) | — |
| Traverse all | O(n) | O(n) | O(n) |

The reference tests insert 0…99 in order into a plain BST and get a tree of **height 100**: sorted input turns a BST into a linked list. That's why real libraries use self-balancing trees.

## In Java

- `TreeMap<K, V>` and `TreeSet<T>` are red-black trees: guaranteed O(log n), plus `floorKey`, `ceilingKey`, `firstKey`, `headMap` and `tailMap`.
- There's no general-purpose tree class to subclass for interview problems; you write `TreeNode` yourself (LeetCode provides it).

<Callout type="warning" title="Common mistakes">

- **Forgetting the `null` base case**: every recursive tree function starts with "if the node is null…".
- **Checking the BST rule only against the parent**: a node must be within bounds set by **all** its ancestors (see [BSTs](/dsa/patterns/bst-patterns)).
- **Assuming a binary tree is a BST**: only use left/right ordering when the problem says it's a BST.
- **Assuming O(log n)**: that holds only for balanced trees. State "O(h)" and explain.
- **Deep recursion** on a degenerate tree of 10⁵ nodes can overflow the stack; use an explicit stack.

</Callout>

## Interview questions

<QA q="What is the difference between a binary tree and a binary search tree?">
A binary tree only restricts the number of children: at most two per node. A binary search tree also orders the values: everything in a node's left subtree is smaller and everything in its right subtree is larger, at every node. That ordering lets search, insert and delete follow one path from the root, which is O(height), and makes an inorder traversal produce sorted output. In a plain binary tree, finding a value can require visiting every node.
</QA>

<QA q="Why can BST operations become O(n), and how do libraries prevent it?">
The cost of BST operations is the tree's height. If keys arrive in sorted order, each new key goes to the right of the previous one, and the tree degenerates into a linked list of height n. Self-balancing trees like AVL and red-black trees perform rotations after inserts and deletes to keep the height O(log n). Java's TreeMap and TreeSet are red-black trees, so they guarantee O(log n).
</QA>

<Practice task="Write the preorder, inorder and postorder of the BST built by inserting 5, 3, 8, 1, 4 in that order. Which order is sorted, and which order lets you rebuild the same BST by inserting again?">

The tree is 5 at the root, with 3 (children 1 and 4) on the left and 8 on the right.

- **Preorder**: 5, 3, 1, 4, 8.
- **Inorder**: 1, 3, 4, 5, 8. This is sorted, as it always is for a BST.
- **Postorder**: 1, 4, 3, 8, 5.

Re-inserting the **preorder** sequence rebuilds the same BST, because each node is inserted before its descendants. That's why preorder is used to serialise BSTs.

</Practice>

<Takeaways>

- A tree is nodes with children and no cycles; root, leaf, subtree, depth and height are the vocabulary.
- Binary, full, complete, perfect, balanced, degenerate, BST, n-ary, trie and heap are the types to know.
- Preorder, inorder and postorder differ only in when the node is visited; level order uses a queue.
- A BST orders values left < node < right, so operations are O(height): O(log n) only when balanced.
- In Java, TreeMap and TreeSet are balanced BSTs; interview trees are TreeNode objects you write yourself.

</Takeaways>
