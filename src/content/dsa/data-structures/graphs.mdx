A **graph** is the most general way to describe things and the connections between them: cities and roads, people and friendships, web pages and links, courses and prerequisites, cells in a maze. Trees and linked lists are special cases. Graphs feel intimidating because they come in so many flavours, but nearly every graph interview question uses the same two traversals, **BFS and DFS**, on one representation, the **adjacency list**.

The vocabulary to know:

- **Vertex (node)**; **edge**.
- **Neighbours** (adjacent nodes); **degree** (number of edges at a node; in- and out-degree for directed graphs).
- **Path**; **cycle**; **connected component**.
- V and E for the counts of nodes and edges.

## How a graph is stored

There are three representations. Interviews almost always want the first:

| Representation | Memory | "Neighbours of u?" | "Edge u–v?" | Use |
| --- | --- | --- | --- | --- |
| **Adjacency list**: for each node, a list of its neighbours | O(V + E) | O(degree) | O(degree) | **Default**; sparse graphs |
| **Adjacency matrix**: `boolean[V][V]` | O(V²) | O(V) | **O(1)** | Dense graphs, small V |
| **Edge list**: `int[][] edges` | O(E) | O(E) | O(E) | Input format; Kruskal's algorithm |

Problems usually give you an edge list. The first thing you do is build an adjacency list:

```java
static List<List<Integer>> buildGraph(int n, int[][] edges) {
    List<List<Integer>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    for (int[] e : edges) {
        g.get(e[0]).add(e[1]);
        g.get(e[1]).add(e[0]);                     // undirected: store both directions
    }
    return g;
}
```

For a directed graph, drop the second `add`. For weights, store pairs: `List<List<int[]>>` with `{neighbour, weight}`. When nodes are strings, use `Map<String, List<String>>`. A **grid** needs no building at all: the neighbours of `(r, c)` are the four adjacent cells inside the bounds.

```java
static int[] bfs(List<List<Integer>> g, int src) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, -1);
    dist[src] = 0;
    Deque<Integer> q = new ArrayDeque<>(List.of(src));
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : g.get(u))
            if (dist[v] == -1) { dist[v] = dist[u] + 1; q.offer(v); }   // first time seen = shortest
    }
    return dist;
}
```

BFS reaches nodes in order of distance, so the first time it sees a node, it has found the **fewest edges** to it. Use it for **shortest paths in unweighted graphs** and anything "level by level".

```java
static void dfsVisit(List<List<Integer>> g, int u, boolean[] seen, List<Integer> order) {
    seen[u] = true;
    order.add(u);
    for (int v : g.get(u)) if (!seen[v]) dfsVisit(g, v, seen, order);
}
```

Use DFS to **explore everything reachable**, count components, find cycles, do topological sorts and backtrack. It doesn't find shortest paths.

Both traversals are **O(V + E)**: every node is visited once and every edge is looked at once from each end. The `seen` (or `dist`) check is essential. Unlike a tree, a graph can lead you back to a node you've already visited, and without the check you'd loop forever. The reference solution checks BFS distances against Floyd–Warshall on thousands of random graphs.

## Operations and their cost (adjacency list)

| Operation | Cost |
| --- | --- |
| Build from an edge list | O(V + E) |
| List the neighbours of u | O(degree(u)) |
| Check whether edge u–v exists | O(degree(u)) (O(1) with a matrix or a set per node) |
| BFS / DFS / connected components | O(V + E) |
| Shortest path, unweighted | O(V + E) with BFS |
| Shortest path, non-negative weights | O(E log V) with Dijkstra |

<Callout type="warning" title="Common mistakes">

- **No visited set**: infinite loops on cycles. Trees don't need one; graphs always do.
- **Marking visited when you poll instead of when you enqueue** (BFS): the same node gets queued many times.
- **Adding an undirected edge in one direction only.**
- **Starting a traversal from only one node** when the graph may be disconnected: loop over every node and start from each unvisited one.
- **Using an adjacency matrix for 10⁵ nodes**: that's 10¹⁰ cells. Use lists.

</Callout>

## Interview questions

<QA q="When would you use an adjacency matrix instead of an adjacency list?">
Use a matrix when the graph is dense (E close to V²) or V is small, and you need constant-time checks of whether a specific edge exists. It costs O(V²) memory regardless of the number of edges, and listing a node's neighbours takes O(V). For the sparse graphs typical of interviews and real systems, an adjacency list uses O(V + E) memory and lists neighbours in O(degree), which makes BFS and DFS O(V + E).
</QA>

<QA q="Why does BFS find shortest paths in an unweighted graph but DFS doesn't?">
BFS processes nodes in order of their distance from the source: everything at distance 1 leaves the queue before anything at distance 2, and so on. So the first time a node is discovered, it's along a path with the fewest edges. DFS follows one path as deep as it can and may first reach a node through a long detour, so the distance at discovery isn't minimal. For weighted graphs neither is enough, and you need Dijkstra's algorithm.
</QA>

<Practice task="A grid of 0s (water) and 1s (land): count the islands, where land cells connect up, down, left and right. Describe it as a graph problem.">

Each land cell is a node; edges join land cells that are adjacent horizontally or vertically. You don't build an adjacency list; the neighbours are computed on the fly. The number of islands is the number of **connected components**. Scan every cell, and when you find unvisited land, increase the count and run BFS or DFS from it, marking every cell of that island visited (or setting it to 0). It's O(R · C) time. See [Graphs & Grids](/dsa/patterns/graph-traversal).

</Practice>

<Takeaways>

- A graph is nodes plus edges between any pairs: directed or undirected, weighted or not, cyclic or acyclic.
- Store it as an adjacency list (O(V + E)); build one from the edge list first. Grids are implicit graphs.
- BFS uses a queue, explores ring by ring, and gives the fewest edges.
- DFS uses recursion or a stack, goes deep, and finds components and cycles.
- Both are O(V + E). Always keep a visited set, and start from every node if the graph may be disconnected.

</Takeaways>
